# 多 Countdown 同屏显示功能规划

> 生成日期：2026-10-03
> 状态：已实现（2026-10-03，含 10 个单元测试）

## 1. 需求背景

当前 countdown 模式只支持单个目标时间（单个 `time` + `title`）。希望通过配置文件同时配置多个 countdown（如 2 个倒计时时间和对应 title），启动时加载并以一定的排列形式同屏显示。

## 2. 合理性分析

1. **与现有架构一脉相承**。项目已有配置文件机制（`~/.config/tclock/config.toml`），timer 模式已支持"多 duration + 多 title"（顺序执行）。countdown 从单实例扩展为列表是自然演进。
2. **实现成本低、风险小**。`Countdown` widget 是无状态的——每次渲染基于 `Local::now()` 现算剩余时间（`src/app/modes/countdown.rs`），不存在计时器状态同步问题。多实例只需 `Vec<Countdown>` + ratatui `Layout` 分块；`render_centered` 本来就支持在给定子区域内居中渲染（`src/app/modes.rs`），可直接复用。
3. **场景真实**。倒数日/纪念日/多个 DDL 同屏是 countdown 类工具的常见诉求。

## 3. 功能设计

### 3.1 配置结构（TOML 数组表，向后兼容）

```toml
# 新写法：多个 countdown
[[countdown.items]]
time = "2026-01-01"
title = "元旦"
order = 1              # 可选：固定显示位置（从 1 开始）

[[countdown.items]]
time = "2026-06-07 09:00:00"
title = "高考"
color = "red"        # 可选：每个实例独立颜色
# show_millis / reverse / size / order 均可 per-item 覆盖
# （注：size 严格按配置渲染，与 timer 一致；格子放不下时截断，不做自动缩小）

# 保留共享默认值（旧写法继续生效）
[countdown]
time = "2026-01-01"      # 旧的单对象写法仍兼容
title = "New year"
show_millis = false
continue_on_zero = false
reverse = false
```

**容错原则**：单个 item 解析失败时跳过并打印警告，而不是整个配置加载失败。当前 `Config::load()` 解析失败直接返回 `None`，一个坏条目会让所有配置静默失效，需一并改进。

### 3.2 目标时间语义

**已确定：不支持周期性时间**，只保留现有 `parse_datetime` 支持的绝对时间点格式（`"20:00"`、`"2026-01-01"`、`"2026-01-01 20:00:00"`、RFC3339）。到期后由用户自行修改配置。

> 注：曾考虑支持每年/每日/每月重复（生日、下班时间、发薪日等），经评估暂不纳入本期范围。

### 3.3 排列 / 布局策略

- **网格自适应（上限 8 个，永不分页）**：

  | countdown 数量 | 布局 |
  |---|---|
  | n = 1 | 全屏（与现状一致） |
  | n = 2 | 上下均分 2 行 |
  | 2 < n < 5 | 4 分网格（2×2），不足 4 个时空位留空 |
  | 4 < n < 7 | 垂直 3 行 × 2 列（3×2），不足 6 个时空位留空 |
  | n > 6 | 8 格网格（4×2），不足 8 个时空位留空 |
  | n > 8 | 只显示前 8 个位置，超出的条目忽略并打印警告 |

  - 始终继续分格，**不做分页**。
- **排序与固定位置**：
  - 每个 item 可配置可选的 `order` 字段（正整数，从 1 开始），使该条 countdown 固定出现在网格的确定位置上。
  - 未配置 `order` 的条目按 `sort` 策略填充剩余空位，默认按剩余时间升序（最近的在前），可配置 `sort = "time" | "config"`。
  - `order` 冲突（多条相同值）时，后配置的条目顺延到下一个空位并打印警告；`order` 超出格子总数时忽略并警告。
- **终端过小行为**：格子放不下时直接截断（与 timer/clock 一致），不做自动缩小。
- **title 缺失时**用目标时间本身作为标题占位。

### 3.4 到期行为

**已确定：结束即停止，显示全 0。** 倒计时到零后定格显示全 0（如 `00:00:00`），**不闪烁、不移除、不继续倒数**，直到用户退出或修改配置。

- 这意味着多实例模式下忽略 `continue_on_zero` 与闪烁逻辑（现有的过零闪烁行为只保留在 CLI 单实例用法中，或一并统一为定格全 0——实现时确认）。
- ~~临期高亮~~（剩余 < 1 小时变色）暂不纳入本期范围。

### 3.5 与 CLI 的关系

`countdown` 子命令的 `--time` 改为可选，且**没有默认配置文件路径**，使用配置文件必须显式指定 `--config`：

- `tclock countdown --config ./xxx.toml`（不带 `--time`）→ 加载配置文件里的全部 countdown 列表同屏显示
- `tclock countdown --time X` → 维持原有单实例行为（CLI 优先于配置）
- `tclock countdown`（既不带 `--time` 也不带 `--config`）→ 报错退出
- `default.mode = "countdown"` 且配置了 items 时，`tclock --config ./xxx.toml` 裸启动即同屏显示

### 3.6 可选项（锦上添花）

- **配置文件热重载**：监听 config.toml 变更自动刷新列表，适合长期挂屏使用。
- **紧凑天数格式**：跨年倒数日剩余几百天时，`format_duration` 输出 `DDD:HH:MM:SS` 很长，多格布局下可提供紧凑格式（如 `123d 4h`）。

## 4. 实现要点

核心工作三块：

1. **配置层**：`CountdownConfig` 从单对象扩展为 `[[countdown.items]]` 数组 + 共享默认值；单项解析失败跳过并警告。
2. **应用层**：`App` 持有 `Vec<Countdown>`，用 ratatui `Layout` 做网格自适应分块渲染。
3. **CLI 层**：`countdown` 子命令的 `--time` 改为可选。
